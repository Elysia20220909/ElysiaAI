01. プロジェクト概要

ElysiaAIは単なるチャットUIではなく、「思考」と「実行」の間に横たわる溝を埋めるために設計された自律型AI-Native OSです。

  • Agent x Decision Tree: 決定木に基づく論理的なステップの自律実行。
  • Sovereign Privacy: ローカルLLM (Ollama) と Milvus Lite を用いた完全ローカルRAG。外部へのデータ流出ゼロ。
  • Resonance Design: ランドリー工場の熱気から着想を得た、強靭かつ美しいUI/UX。

07. セキュリティ: AEGIS Ledger

ElysiaAIのセキュリティ基盤「AEGIS Ledger」は、Sovereign Privacyを実現するための多層防衛(Multi-layer ICE)システムです。

実装のハイライト (予定)

  • ローカル完結型処理: 全てのLLM推論とRAG検索はローカルデバイス内で完結。
  • Tool Execution Sandbox: AIによるツール実行(ファイル書き込みやコマンド実行等)は、厳格に制限されたサンドボックス内で評価・実行。
  • JWT認証: Web UIとBunバックエンド間のセキュアなセッション管理。
  • 暗号化メモリ: MilvusLiteに保存されるベクトルデータおよびSQLiteの機密データ保護。

構造化エラーオブジェクト

ElysiaAIの全レイヤー（Bun, Python, フロントエンド）で統一されたエラーフォーマットを使用し、自動復旧やリトライの判断をプログラムが自律的に行えるようにします。

interface ElysiaError {
  code: string; // 例: "ERR_OLLAMA_VRAM"
  message: string; // システム向け詳細
  hint: string; // ユーザー向け解決ヒント
  retryable: boolean; // 自動リトライ可能か
}

フルスタック障害フロー

sequenceDiagram
    participant F as Frontend
    participant B as Bun Backend
    participant P as Python Kernel
    participant O as Ollama
    
    F->>B: リクエスト送信
    B->>P: IPC呼び出し
    P->>O: LLM推論リクエスト
    O-->>P: エラー発生 (例: VRAM不足)
    
    P->>P: エラー解析 (ElysiaError生成)
    P-->>B: {code: "ERR_VRAM", retryable: true...}
    
    alt retryable == true
        B->>B: 再試行ロジック実行 (コンテキスト縮小等)
        B->>P: 再リクエスト
    else retryable == false
        B-->>F: エラーとHintを返却
        F->>F: ユーザーに解決策をUI提示
    end

実装例 (Bun Middleware)

// Bun/Elysia.js 側でのエラーハンドリングミドルウェア
app.onError(({ code, error, set }) => {
    // 構造化エラーかチェック
    if (error && error.code && error.hint !== undefined) {
        set.status = 400;
        return {
            success: false,
            error: {
                code: error.code,
                message: error.message,
                hint: error.hint,
                retryable: error.retryable
            }
        };
    }
    
    // 未知のエラーは汎用フォーマットにラップ
    set.status = 500;
    return {
        success: false,
        error: {
            code: "ERR_UNKNOWN",
            message: "予期せぬシステムエラーが発生しました。",
            hint: "システム管理者に連絡するか、ログを確認してください。",
            retryable: false
        }
    };
});
10. Decision Tree 仕様 (Autonomous Reasoning Engine)

エージェントが自律的にタスクを完了させるための決定木（Decision Tree）ロジックの詳細です。

graph TD
    Start((リクエスト受信)) --> Intent[Intent Classifier Node]
    
    Intent -->|知識が必要| RAG[Knowledge Retrieval Node]
    Intent -->|直接回答可能| Direct[Direct Response Node]
    Intent -->|ツール操作が必要| Plan[Action Planning Node]
    
    RAG --> Plan
    Plan --> Execute[Tool Execution Node]

    Evaluate -->|成功・タスク完了| Finalize[Finalize Response Node]

    Direct --> Finalize
    Finalize --> End((レスポンス返却))

Intent Classifier Node (意図分類)

ユーザーの入力を解析し、「単なる質問」「外部知識が必要な質問」「システム操作が必要なタスク」のいずれかに分類します。この分類精度が全体のパフォーマンスを左右します。

Tool Execution Node (ツール実行)

後述の「Tool Sandbox」内でシステムコマンドやファイル操作を実行します。実行結果の標準出力/標準エラー出力を取得し、次のVerification Nodeに渡します。

Verification Node (自己評価・検証)

ツールの実行結果や生成された回答が、ユーザーの要求を満たしているか（Resonance Loopの終了条件）を自己評価します。エラーが含まれていれば再度プランニングに遷移します。

11. AEGIS Ledger 詳細 (Security Architecture)

Sovereign Privacy（主権的プライバシー）を保証するための多層防衛システム「Multi-layer ICE」の全貌です。

01

Layer 1: Edge Auth

WebSocketおよびHTTP APIのエントリーポイント。Bun/Elysia.jsによる高速なJWT検証とRate Limitingを実施。

Algorithm: EdDSA (Ed25519)
02

Layer 2: Core IPC Crypto

BunとPython Kernel間のローカルプロセス間通信（IPC）においてもペイロードを暗号化し、メモリスニッフィングを防止。

Protocol: TLS 1.3 over Unix Socket
03

Layer 3: Memory Masking

Milvus Liteへ保存されるベクトルデータ（RAG）の保存前マスキング。PII（個人情報）を検知してハッシュ化または伏せ字に置換。

Analyzer: Presidio + Local NER Model
04

Layer 4: Immutable Ledger

AIが実行する全コマンド・ファイル操作はSQLiteに「Append-Only（追記のみ）」で記録。ハッシュチェーンで改ざんを防止。

Mechanism: Cryptographic Hash Chain
12. セットアップ手順詳細 (Development Setup)

ElysiaAIの開発および実行環境を構築するための詳細なステップです。

Step 1: 前提条件 (Prerequisites)

  • Bun (v1.1以上): フロントエンドおよびバックエンドサーバー用
  • Python (v3.11以上): AIカーネルおよび推論エンジン用
  • Ollama: ローカルLLM実行用（llama3.2 を pull しておくことを推奨）
  • Make: ビルドおよび起動スクリプト実行用

Step 2: 環境変数の設定 (.env)

リポジトリルートの .env.example を .env にコピーし、以下の変数を設定します。

# Server Settings
PORT=3000
PYTHON_PORT=8000

# Security
JWT_SECRET="your-super-secret-key"

# Database & Memory
DATABASE_URL="file:./dev.db"
MILVUS_URI="./milvus_memory.db"

# LLM Configuration
OLLAMA_BASE_URL="http://localhost:11434"
DEFAULT_MODEL="llama3.2"

Step 3: 依存関係のインストール (make install)

make install コマンドを実行すると、以下のプロセスが自動で走ります。

  1. Bunパッケージのインストール: bun install によりフロント/バックエンドの依存を解決
  2. Python仮想環境の構築: .venv を作成し、pip install -r requirements.txt を実行
  3. データベースの初期化: bunx prisma db push でSQLiteをセットアップ
  4. モデルの事前確認: Ollamaサーバーとの疎通確認およびモデルの存在チェック

Step 4: システム起動 (make boot)

make boot コマンドにより、Resonance Loopが起動します。

バックグラウンド Python Uvicornサーバーがポート 8000 で起動し、AIカーネルとMilvusデータベースが初期化されます。
フォアグラウンド Bun/Elysia.js サーバーがポート 3000 で起動。http://localhost:3000 でWeb UIにアクセス可能になります。
