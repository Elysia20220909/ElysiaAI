# Discord Server Spec: 1086031216433713163

対象DiscordサーバID: `1086031216433713163`

この仕様書は、IDだけで実サーバ内部を取得できない前提で作る **標準ルール・仕組み設計書** です。
実際のチャンネル名、ロール名、権限はサーバ内の現物に合わせて差し替えます。

## Purpose

このサーバは、ElysiaAI / GINROU / ローカルAI運用の司令室として扱う。
雑談、作業報告、検証、通知、ログを分離し、荒れない、漏れない、追える状態を保つ。

```text
見る場所を決める。
話す場所を分ける。
権限を絞る。
ログを残す。
秘密を出さない。
```

## Permission Policy

## Server Rules

1. 秘密情報を投稿しない。
2. APIキー、Webhook URL、Bot Token、パスワード、セッション情報を貼らない。
3. 個人情報、住所、電話番号、ログイン情報を晒さない。
4. 荒らし、連投、過度な煽り、晒し行為を禁止。
5. NSFW、違法行為、権限回避、マルウェア作成依頼を禁止。
6. 検証・セキュリティ話題は `#security-lab` に分離する。
7. 実システムへ影響する作業は、目的、範囲、戻し方を明記する。
8. Botや自動化はログを残す。隠れた操作を作らない。
9. 依頼は `#requests`、不具合は `#bug-report` に分ける。
10. 管理者判断で削除、timeout、kick、banを行う場合がある。

## Moderation Flow

| Severity | Action |
| --- | --- |
| Low | 注意、誘導、投稿整理 |
| Medium | メッセージ削除、短時間timeout |
| High | 長時間timeout、kick |
| Critical | ban、Webhook/token rotation、監査ログ保存 |

Critical examples:

- Token / webhook leak.
- 個人情報晒し。
- マルウェア、侵害、権限回避の実行支援。
- Bot権限の悪用。

## Onboarding Flow

1. User joins.
2. User reads `#rules`.
3. User gets `Guest`.
4. Staff or verification bot assigns `Member`.
5. Lab参加者だけ `Lab` を付与。
6. OperatorはOwner/Adminが手動付与。

## Audit Checklist

Weekly:

- Webhook投稿先が専用チャンネルだけか確認。
- BotにAdministrator権限がないか確認。
- `#audit-log` に重要操作が残っているか確認。
- 招待リンクが無期限・無制限になっていないか確認。
- Staffロール保持者を確認。

Monthly:

- 使っていないWebhookを削除。
- Bot token rotationを検討。
- チャンネル権限の継承崩れを確認。
- ルール文を現状へ更新。
