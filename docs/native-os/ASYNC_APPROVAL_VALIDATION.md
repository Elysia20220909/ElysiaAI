# M5c: 承認待ち中の処理継続と終了時回収

固定した RAM 読み取り操作を提案した後も、ユーザープロセスが計算を続けられるようにした。
`async-*` は起動モード55を使う。従来の `operator-*` は同期入力の回帰試験として残す。

## 処理の流れ

資料サービスは提案を Proposed として永続化し、入力を待たずに IPC の応答を返す。
クライアントは独立した加算処理を続け、読み取り専用の syscall 8 で操作状態を確認する。
この syscall はモード55のクライアントに限定され、承認や権限の変更はできない。

カーネルはタイマー割込みごとに COM1 を最大16 bytes だけ読み取る。
行は最大32 bytesで、`approve 1` または `deny 1` のみを受け付ける。
期限は提案から500 ticksと Plan の deadline の早い方で、現在の PIT 設定では最大約5秒のゲスト時間となる。
期限と入力が重なった場合は期限を優先する。途中まで届いた行も期限を延ばさない。
CPU tick とフレームの上限は既存の起動定義から増やしていない。

承認は表示した Plan 全体に結び付け、実行時に内容、権限、期限を再検査する。
承認後の入力変更と二重実行は拒否する。拒否は Denied、無入力や不正入力は Interrupted を保存する。
判断した時点で VM を終了せず、クライアントに結果を返す。クライアントの終了後、
サービスも通信切断を受けて終了し、両者のアドレス空間、通信、資料権限を回収する。
試験用 VM は、回収後の最終判定を終えてから終了する。

プロセス終了時に Proposed / Approved / Running が残っていれば、Interrupted / Unknown を永続化する。
既に終わった状態は二重に追記しない。承認セッションも破棄し、古い入力を使い直さない。
再起動時は以前と同じく記録の読み取りだけを行い、承認や実行権限を復元しない。

## 検証

| ケース | 操作結果 | 実行回数 |
| --- | --- | --- |
| async-approve | Completed | 1 |
| async-deny | Denied | 0 |
| async-invalid | Interrupted | 0 |
| async-wrong-id | Interrupted | 0 |
| async-timeout | Interrupted | 0 |
| async-replay | Completed | 1 |

自動入力は、提案表示後にクライアントの計算結果とタイマー割込みの両方が観測されるまで送らない。
ホストの試験入力は UART の受信バッファを一括送信で埋めないよう、8 bytesずつ20 ms間隔で送る。
全ケースで判断前の進行、判断後の正常終了、両プロセスの回収、空きフレーム数の復元を要求する。
同じディスクで再起動して旧承認を送っても、ユーザー起動や記録の追記がなく、ディスクハッシュが不変であることを確認する。
Rust の単体試験は遅延した改行、部分入力、過大入力、無入力、再利用拒否、終了時の一度だけの記録を検査する。
Python の判定器は進行証拠や回収証拠の欠落、終了値の誤り、資源減少を成功としない。

```powershell
python native-os/tools/boot_test.py --case all --qemu <qemu-system-x86_64.exe> --firmware-dir <share>
```

手動入力の入口は `--case async-approve --operator-manual`。
5秒は最小の試験用期限で、人向けの実用的な待ち時間ではない。
ログと専用ディスクは `native-os/out/async-*/operator-*/` に残る。

## 制限

固定した2プロセスと1操作の検証であり、第三のアプリや複数の同時承認は扱わない。
クライアントの計算が進むことを実証する。待機中の全プロセスを眠らせる idle 機構は今回の範囲外。
UART 割込みドライバーではなく、タイマーで短い入力処理を行う。永続記録のディスク I/O は
従来の同期処理なので、ストレージ待ちまで非同期化したわけではない。厳密な CPU 時間課金も提供しない。

COM1 のホスト側を信頼する境界と、記録の認証や実電源断耐性に関する
[従来の制限](OPERATOR_APPROVAL_VALIDATION.md)は変わらない。
AI 推論、実機、本人認証、人による対話入力はこの試験では検証しない。

## 実行結果（2026-09-21）

Windows、Rust 1.96.0、固定 QEMU 11.1.0 のヘッドレス試験で、最終的に69ケースを確認した。
初回の全体試験は67/69成功。不正入力の2ケースが timeout となったため、ホスト入力を
分割送信する修正を行い、影響する承認12ケースと参照する正常実行1ケースを再実行して13/13成功した。
それ以外の56ケースは初回の成功結果を使用している。

Rust 65/65、Python 32/32、Rustfmt、ホストとカーネルの Clippy、変更した Python の Ruff は成功。
ステージ済み差分検査と Gitleaks も成功し、秘密情報の検出は0件だった。
人が端末で入力する対話試験と実機試験は未実施。
