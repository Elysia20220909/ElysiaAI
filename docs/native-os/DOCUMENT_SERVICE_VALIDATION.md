# M3b RAM 資料サービスの検証

M3a の `8981685e525870a4aa4cb3fca2e9b8e4b36ccbe8` を基に、固定した資料を IPC 経由で
読み取るサービスを追加した。ビルド・ABI は [native-os](../../native-os/README.md)。
M1〜M3a の記録は当時の証拠として変更せず残す。

## 実装した境界

クライアント pid 0 とサービス pid 1 は、別のアドレス空間の Ring 3 プロセスとして動く。
カーネルの読み取り専用領域に合成資料を 2 件置き、各主体に異なる資料の権限を発行する。
クライアントが読めるのは `ELYSIA RAM GUIDE\n` だけである。もう一つの資料の正規ハンドルを
試験で公開しても、クライアントの権限表にないため拒否する。値の秘密性には依存しない。

要求は操作・ハンドル・オフセット・長さの 32 bytes。カーネルが IPC メッセージのコピーを
サービスへの配達時に保留し、固定 2 者の通信相手を送信者として記録する。要求内に PID はない。
サービスの syscall 6 はこの要求だけを一度処理する。ユーザーの受信バッファを再解釈しないので、
配達後のバッファ書き換えで対象や送信者を変えられない。

| 検査 | 動作 |
| --- | --- |
| 権限 | 実際の送信者が所有するハンドル・世代を照合し、権限が指す資料だけを対象にする |
| 範囲 | offset + length の桁あふれ、資料外、48 bytes を超える要求を拒否。末尾のゼロ長読み取りは許可 |
| 形式 | 要求はちょうど 32 bytes。write 等の未知の操作は -38 |
| 応答 | 64 bytes をゼロ初期化し、状態・長さ・データを設定。拒否時の長さ・データはすべて 0 |
| 再実行 | 保留要求がある間の次の receive と、消費済み要求の再処理は -11 |
| 応答先 | 所有する書き込み可能なページだけ。拒否時は要求を消費せず再試行できる |
| 失効 | 所有者の revoke が成功した時点で今後の読み取りを拒否。別主体の権限は失効できない |
| 終了 | 終了・故障・tick 上限時の共通経路で要求・権限を破棄。サービス終了は両者の資料権限を破棄 |

失効は既に返したデータを取り消さない。保留メタデータは無効化して再利用するもので、
カーネル RAM 全体の暗号学的消去は保証しない。静的な合成資料はカーネル内に残る。

サービスは応答ループを担うが、資料の保管と権限の強制はカーネル内にある。
汎用ファイルサーバーや完全なユーザー空間のストレージではない。悪意あるサービスが正しい応答を
返すことや、既に受け取った許可済みデータを忘れることは保証しない。
任意の通信先に拡張するときは、固定の `1 - pid` に代えてカーネル内の送信元情報を渡す必要がある。

## 試験ケース

| ケース | ユーザー空間で確認する結果 |
| --- | --- |
| document-read | 17 bytes の実データ、部分読み取り RAM、末尾ゼロ長を比較 |
| document-denied | 無効・別主体の正規ハンドルを -9、write を -38、31 bytes の要求を -22。拒否応答の残部は 0 |
| document-revoke | 許可済み読み取り→自分の権限を失効→同じハンドルの読み取りを -9 |
| document-range | 桁あふれ・末尾外を -22、応答容量超過を -90 |
| document-service-exit | 要求を受信後にサービスが終了。クライアントは -32 を受け、送信も拒否され正常終了 |
| document-service-fault | 同じ箇所でサービスが #UD。故障を隔離し、クライアントは -32 を受けて正常終了 |

クライアントからの syscall 6 を -13、サービスのコード領域への書き込みを -14 とし、
次の正しい呼出しが成功することも検査する。処理前の追加受信と処理後の再実行は -11。
ゲスト内の実データ比較に加え、ホストの判定器は応答状態の順序・回数、待機・起床・停止の整合、
両者の回収、空きフレーム数の復元を確認する。ゲストの合格コードは 49、runner は 0。

## 負の対照

保護を一つずつ一時的に外して同じ QEMU 試験を行い、各変更を元の bytes に戻した。
4 件とも guest 255 / runner 1 となり、正常成功として扱われなかった。

| 省略した保護 | 失敗したケース |
| --- | --- |
| 所有者の表ではなく、全主体の表からトークンを探す | document-denied |
| revoke 時の権限除去 | document-revoke |
| 処理時の保留要求の消費 | document-read |
| 終了時の資料権限・保留要求の回収 | document-service-exit |

回避コードや試験用の無効化フラグは最終ソースに残していない。

## 検証の限界

Windows 上の固定 QEMU / UEFI、1 CPU、2 プロセス、合成データだけを対象とする。
各プロセスの制限は PIT の累積 64 tick で、厳密な CPU 時間課金ではない。
資料状態を含む予算停止の独立ケースは追加しておらず、終了・故障と同じ回収経路を使用する。
権限の委譲・派生、サービスの再起動 API、任意アプリのロード、永続化、AI 推論、実機は未対応。
ホストの資料やホーム、ネットワークをゲストに公開しない。既存依存を使い、新しい依存・CI・hook を追加しない。
依存元の確認範囲は [DEPENDENCIES](../../native-os/DEPENDENCIES.md) を引き継ぎ、
エミュレーター全体の監査や新規マシン全体の環境構築まで実証したとはしない。
