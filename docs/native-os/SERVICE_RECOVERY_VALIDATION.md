# M3c サービス復旧の検証

PR #116 をマージした `1d63ceb2b287f2667bebe48625be7e45a278a90c` を基準に、
クライアントを残した資料サービスの再起動を追加した。対象は固定の 2 プロセス。
[ビルド・ABI](../../native-os/README.md) と [M3b の資料サービス](DOCUMENT_SERVICE_VALIDATION.md) を参照する。
以前の検証記録は当時の証拠として残す。

## 復旧の流れ

1. サービスが正常終了・同期例外・累積 64 tick 上限に達すると、カーネル root に移って終了処理する。
2. サービスの通信・資料権限と保留要求を無効化し、所有フレームを消去・返却する。受信待ちのクライアントへ -32 を返す。
3. クライアントが syscall 7 で再接続を要求する。既存サービスがある場合と、再起動 8 回の上限を超える場合は -11。
4. 別の一時オブジェクトで新しい権限を準備し、新サービスのアドレス空間を構築する。失敗時は部分確保を回収する。
5. 構築完了後、割り込み無効の区間でサービス・通信・資料権限・世代をまとめて公開する。クライアントへ新しい 3 個のハンドルを返す。
6. クライアントは新しい読み取り要求を送る。失われた要求の自動再送や、副作用の再実行は行わない。

クライアントの root、保存レジスター、データ、スタック、累積 tick は置き換えない。
テストでは root の一致をカーネルが検査し、クライアントが自分のデータに置いた値の保持を確認する。
サービスのプロセス番号は 1 のまま再利用するが、frame と所有メモリは初期化し、予算計測を新しく開始する。
新しいサービスはデータページに前世代の値がないことをユーザー空間でも確認する。

## 権限と失敗時の扱い

再接続を要求できるのは固定クライアント pid 0 だけ。サービスからの呼出しは -13。
成功時に返す 24 bytes の領域は、クライアントの書き込み可能な所有ページに限る。
形式不正は -22、書けない出力先は -14 とし、権限やプロセスを作り直す前に拒否する。

旧チャネルと資料表の世代・単調増加する発行値を引き継ぐ。旧 send / receive / 資料ハンドルは -9。
権限を新しく作る途中で失敗しても、公開中の状態や出力先を先に変更しない。
新プロセス構築に失敗すると -12 を返す。クライアントは同じ接続状態から再試行できる。
試験では一度だけ 3 フレームの確保上限で部分構築を失敗させ、回収後の再試行を確認する。

これは初期ポリシーで認めた資料 0 への再接続である。以前のハンドルを復活させず、
新しい接続に対して読み取り権限を発行する。接続単位の revoke は永続的な禁止ではない。
ユーザー承認の永続記録、期限、任意の権限委譲・派生は未実装。

成功した再起動は最大 8 回。失敗した構築はこの回数を消費しないが、クライアントの累積
1024 tick 上限を維持する。サービスは各世代 64 tick。無制限の再起動を許さない。
待ち時間制御、backoff、厳密な CPU 時間課金、複数のサービスを監督する仕組みは範囲外。

## QEMU のケース

| ケース | 必須の結果 |
| --- | --- |
| recovery-fault | 要求を受信したサービスの #UD を隔離。再接続後に旧ハンドルを拒否し、17 bytes の資料内容を比較 |
| recovery-exit | 同じ箇所で正常終了。クライアントは切断を受け、新しいサービスから読み取りを再開 |
| recovery-budget | サービスの無限ループを 64 tick で停止・回収。再接続後に正常な読み取り |
| recovery-repeat | 8 回の故障・再接続。毎回、旧権限拒否と読み取り再開、空きフレーム数の一致 |
| recovery-allocation | 再起動時の部分確保を一度失敗させる。空き数・クライアント出力の保持後、再試行が成功 |
| recovery-limit | 8 回の再起動後の故障に対し、9 回目を -11 で拒否。クライアントは終了し、全資源を回収 |

各ケースで、生きたサービスの置換を拒否し、不正な応答先と長さを拒否する。
再接続後の最初の要求には前世代の資料ハンドルを入れ、-9 とゼロ埋めの応答を確認する。
その次に新しい権限で資料の全内容を確認する。クライアントの進捗は自身のデータとレジスターに残す。

判定器は、停止・回収→世代更新→実行の順序、切断通知の件数、世代ごとの空きフレーム数、
旧権限の拒否、再開した読み取り、最終回収を確認する。停止したサービスが世代更新前に
再実行されたログや、回収漏れ・必要な拒否の欠落は失敗にする。

## 負の対照

以下の保護を一つずつ一時的に外した。4 件とも guest 255 / runner 1 で失敗を検出した。
各試験後に元の bytes に戻し、最後の全件試験には回避コードを残していない。

| 変更 | 検出したケース |
| --- | --- |
| チャネルの発行値を初期値へ戻す | recovery-fault |
| 資料権限の発行値を初期値へ戻す | recovery-fault |
| サービスの所有フレームを返却しない | recovery-fault |
| 8 回の再起動上限を外す | recovery-limit |

## 残る範囲

Windows 上の固定 QEMU / UEFI、1 CPU、固定資料と固定プロセスだけを対象とする。
実機、任意プログラムのロード、汎用サービス管理、AI 推論、永続データの復旧は未対応。
ホストの資料・認証情報・ホーム・ネットワークをゲストへ公開しない。
依存関係・インストール・hooks・CI・同梱バイナリ・認証情報・外部通信の境界は
[DEPENDENCIES](../../native-os/DEPENDENCIES.md) の確認範囲を引き継ぐ。新しい依存や実行ツールは追加しない。
