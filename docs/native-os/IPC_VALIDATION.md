# M3a 通信と権限の検証

M2c の `ff0cb6e8d278405f2fbb4414ce9c63815cb94611` を基準に、固定した 2 プロセス間の
IPC、操作権限ハンドル、受信待機と起床、通信相手の終了時の回収を実装した。
これは M3 の最初の実装単位であり、一般的な権限委譲や RAM 資料サービスの完成ではない。
実装・再現手順は [native-os](../../native-os/README.md)。M1〜M2c の記録は当時の証拠として残す。

## 通信と権限の境界

| 対象 | 実装 |
| --- | --- |
| 通信路 | 2 者の双方向チャネルを 1 個。各方向の待ち行列は 2 件、1 メッセージ最大 64 bytes |
| 所有 | 各プロセス専用の権限表に send / receive を登録。ユーザーのハンドルを表と照合し、所有者・操作権限・チャネル世代を確認 |
| ハンドル | 単調増加する値。世代と発行値を再初期化せず、桁あふれ時は新しい発行を拒否。値の秘密性に依存しない |
| 送信 | 所有する読み取り範囲を確認してカーネル内へコピー。後から送信元を書き換えてもキュー内の内容は変わらない |
| 受信 | 所有する書き込み可能な範囲だけを許可。コード、カーネル領域、他プロセスのページ、桁あふれを拒否 |
| 待機 | 空の receive は frame と数値の受信先情報を保存し、プロセスを runnable から外す。カーネル内で待ち続けない |
| 起床 | メッセージ到着時に受信先を再検査し、そのプロセスの CR3 でコピー。保存した返り値を設定して runnable に戻す |
| 失効 | receive 権限でチャネル全体を revoke。世代を進めて古い権限を拒否し、両方向のキューを破棄。保留中の receive には -32 |
| 相手終了 | 正常終了、同期例外、tick 上限による停止は共通の終了経路でチャネルを閉じる。キューを破棄し、待機相手へ -32 を返す |
| 回収 | 待機中と終了済みを区別し、終了したプロセスだけのメモリを回収。両者の終了後に権限表・キュー・待機情報の残存と空きフレーム数を検査 |

チャネルは 2 者に固定する。片方の終了で、両方向の未受信メッセージは失われる。
send 成功はカーネルのキューへコピーできたことを意味し、相手の処理完了や永続化を保証しない。
送信キューが満杯なら待たずに -11 を返す。受信容量が足りない場合は -90 とし、メッセージを残す。
ゼロバイトのメッセージも 1 件として数えるため、上限をすり抜けない。

2 者とも受信待ちになる要求は、二人目へ -35 を返す。外部の送信者やデバイスを持たない
現在の構成に限る判定であり、一般的なデッドロック検出ではない。

権限ハンドルの値は推測可能でも、自分の表に発行されていない権限では操作できない。
試験では相手の正規ハンドルをあえて渡し、それを使っても拒否されることを確認する。
ユーザーによる権限発行・移譲・派生、任意エンドポイント、ACL、共有メモリはまだ提供しない。

## CPU とメモリ

M3a の試験でも PIT を約 100 Hz で動かし、各プロセスを最大 64 tick に制限する。
カーネルのハンドラーは割り込み無効で動き、IPC の検査・コピー・起床は固定した件数と長さで終える。
待機中は実行対象から外すため、ユーザーの受信ループで CPU を消費しない。

起床時のコピーでは一時的に受信者の CR3 へ移り、コピー後は呼出し元の CR3 へ戻す。
待機しているプロセスのページを解放せず、生きたマッピングを前提に毎回範囲を確認する。
プロセスの終了時は M2c と同じくカーネル root へ移ってから所有フレームを消去・返却する。
チャネル管理と待ち行列の格納領域は固定長のカーネル領域で、内容を消去して再利用する。

## QEMU の試験

| ケース | 必須の結果 |
| --- | --- |
| `ipc-echo` | AX、BY の 2 件をコピーして応答。送信元変更の影響を受けない。不正・別主体のハンドル、異なる操作権限、過大な長さ、書けない受信先を拒否。短い受信ではメッセージを失わない |
| `ipc-peer-exit` | pid 0 の受信待機中に pid 1 が終了。pid 0 を -32 で再開し、正常終了まで継続 |
| `ipc-peer-fault` | 同じ待機中に pid 1 が #UD。故障を隔離し、pid 0 へ -32、両者の資源回収 |
| `ipc-revoke` | 受信権限で通信を失効。待機中の呼出しは -32、古いハンドルの再利用は -9、キューを破棄 |
| `ipc-deadlock` | 二人目の受信待ちに -35。そのプロセスが送信すると先に待っていた相手が再開し、終了できる |
| `ipc-queue` | 2 件を超える送信を -11 で拒否し、終了時に未受信メッセージを消去 |

既存 21 ケースも同じカーネルで再実行する。M3a のゲスト終了コードは 49、runner の成功は 0。
判定器は待機・起床・終了の順を追い、待機中や停止後の実行、起床の欠落、資源の残存を拒否する。

ホストの単体テストでは同じチャネル実装を使い、権限所有、操作権限、FIFO 順、キュー上限、
短い受信での保持、ゼロ長メッセージ、失効後と新世代での旧ハンドル拒否、桁あふれを検査する。
128 回のチャネル再生成で内容と権限が残らないことも検査する。この反復はホスト試験であり、
QEMU での 128 チャネル再生成を実測したものではない。

## 負の対照

次の 7 種類を通常ソースへ一時的に注入し、すべて guest 255 / runner 1 として検出した。
各回の後で元のバイト列へ戻し、回避用ビルド設定は残していない。

| 省略・破壊する処理 | 実測した失敗 |
| --- | --- |
| 別主体の権限を受け付ける | `ipc-fixture-verdict` |
| 操作権限の検査を省略 | `ipc-fixture-verdict` |
| revoke で世代を進めない | `ipc-fixture-verdict` |
| 待機中の受信者を起こさない | `ipc-stalled` |
| 送信キューの上限を省略 | `ipc-fixture-verdict` |
| 受信バッファの書き込み範囲検査を省略 | `ipc-fixture-verdict` |
| 相手終了時のキュー消去を省略 | `ipc-resource-leak` |

## 未実装・未検証

- 2 者以外の IPC、権限委譲・派生と連鎖失効、一般的なサービス管理、RAM 資料サービスは未実装。
- プロセス作成 API、任意 ELF、IPC のタイムアウト指定、優先度継承、配送保証は未実装。
- CPU 上限は粗い tick 計測。厳密な CPU 時間課金や実時間期限、カーネル自身の無限ループ回復は保証しない。
- SMP、実機向け APIC、FPU/SIMD 保存復元、実機起動、Secure Boot、DMA・サイドチャネル対策は範囲外。
- 既存の AI アプリを移植しておらず、ゲスト内の AI 推論、ネットワーク、永続化は含まない。
