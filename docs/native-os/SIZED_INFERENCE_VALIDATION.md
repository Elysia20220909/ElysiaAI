# 独自カーネルでのサイズ別推論とページ予算の評価

2026-09-25、独立したRing 3の `elysia-sized-inference` ELFを追加した。
生成したi32入力とi32重みの密行列積を計算し、i64出力を推論arenaへ保存する。
これはサイズを変えた実計算の計測であり、学習済みモデルやLLMではない。

## 実装と境界

- 既存の推論ELFはRX領域の上限に近いため、計測用の小さな専用binを同じRust packageへ追加した。
- 起動モード75〜86が固定12形状を選ぶ。任意モデルのロードや外部manifestは追加していない。
- `Shape::layout` が次元を検査してからサイズを計算する。入力・重み・出力を連続して置き、出力を8 bytesへ整列する。
- 全入力・全重み・全出力へvolatileでアクセスし、最適化による計算やメモリアクセスの消去を避ける。
- syscall 9で必要ページを確保し、計算後に全解放する。CPU上限1024 tick、arena上限16ページ、総フレーム上限32を維持する。
- ホストは形状と計算結果のchecksum、実際のarena要求と割り当て、プロセス終了、全フレームの回収を照合する。
- 資料サービスは独立して動き、そのarena確保は拒否される。操作はEmpty・実行0回で、journalディスク全体は不変でなければならない。

予測対象は、カーネルの `arena-resize` ログから抽出した **割り当てページ数のピーク**。
Pythonのtracemalloc、ホストのRSS、プロセス全体のメモリとは区別する。
小さいモデルを読み込みやすくする機能や、分類精度の評価ではない。

## 固定した実験設計

形状は `(batch, features, classes)`。各形状を新しいQEMU起動で2回計測する。

| 用途 | 形状 |
| --- | --- |
| 学習6件 | (1,128,8), (4,128,8), (1,256,16), (4,256,16), (1,384,24), (4,384,24) |
| 補正2件 | (2,192,12), (3,320,20) |
| 評価4件 | (2,128,8), (3,256,16), (2,384,24), (8,384,24) |

`native_sized.py` は入力KiB・重みKiB・定数項から、各学習形状の実測最大ページ数へ線形回帰する。
Ubuntu側のサイズ実験と同じ小さな連立方程式ソルバーを利用するが、予測対象と学習データはnative専用である。
補正データの正の残差の最大値に1ページを足して余裕を設け、予測を整数ページへ切り上げる。
各次元が学習範囲を外れる場合や不正なモデル値では固定16ページへ戻す。
全提案は `apply=false` で、今回の計測時上限は16ページのまま。

評価用QEMUを起動する前に `frozen-model.json` へモデルと評価4件の提案を保存する。
失敗時は `completed=false` とエラーを記録する。収集先は新規ディレクトリに限定し、以前の結果を上書きしない。
学習・補正・評価の各反復で、serialログ、起動前の識別情報、runnerのreportをコピーする。
再解析時はハッシュ、終了コード、形状、計算結果、上限・回収、カーネル・専用ELF・QEMU・環境の一致を検査する。
これは署名されていないローカルの実験記録であり、第三者への実行証明ではない。

## 結果

Windows上の固定QEMU 11.1.0 / q35 / TCG / 1 CPU / 256 MiBで24回の計測に成功した。
Ubuntuで保存済みログを再解析し、同じ予測と判定を得た。QEMU自体をUbuntuで実行した記録ではない。

| 評価形状 | 実測ピーク（ページ） | 回帰＋余裕の提案（ページ） | 解析式（ページ） |
| --- | ---: | ---: | ---: |
| (2,128,8) | 2 | 4 | 2 |
| (3,256,16) | 5 | 7 | 5 |
| (2,384,24) | 10 | 12 | 10 |
| (8,384,24) | 13 | 16（学習範囲外） | 13 |

固定16ページ、回帰による提案、解析式の三方式とも評価4件の実測を収めた。
解析式は今回の既知の配置に対する次の式で、全評価形状の実測値と一致した。

```text
input_bytes  = batch * features * 4
weight_bytes = classes * features * 4
output_bytes = batch * classes * 8
pages = ceil((align_up(input_bytes + weight_bytes, 8) + output_bytes) / 4096)
```

**この固定配置では解析式が最も正確であり、学習方式の優位性は確認していない。**
回帰結果は、サイズ特徴量とnativeの計測を接続する評価基盤として扱う。
低い予算を実際に適用した効果、使用メモリの削減、実機性能向上を示す結果ではない。
TCG上の所要時間やタイマー割り込み回数は実機の推論性能の比較に使わない。

## 再現

新しい収集先を指定する。QEMUとfirmwareは既存runnerが版を検査する。

```powershell
python experiments/agent_policy_lab/native_sized.py --collect --run-dir experiments/agent_policy_lab/out/native-sized-new --qemu <qemu-system-x86_64.exe> --firmware-dir <share>
```

収集に成功したディレクトリをWindowsまたはUbuntuで再解析する。

```sh
python3 experiments/agent_policy_lab/native_sized.py --run-dir experiments/agent_policy_lab/out/native-sized-20260925
python3 -m unittest discover -s experiments/agent_policy_lab -p 'test_*.py'
```

今回の保存先は `experiments/agent_policy_lab/out/native-sized-20260925/`。
既存runnerのケース別出力は各起動で更新されるが、ここには各反復のログを独立に保存している。
再解析はこのコピーを使うため、その後の通常のQEMU試験でケース別ログが更新されても影響しない。

Rustライブラリ試験80件、Python判定器51件、研究用試験24件が合格した。
研究用試験はWindowsとUbuntuで確認した。負例は形状・checksum・上限・回収・ディスクの変更、
評価データの学習側混入、反復欠落、異なるバイナリの混在、保存済みモデルやログの変更を検出する。
Clippyはホストlib・ゲストkernel・推論2bin・UEFIローダーで警告をエラー化して確認した。

## 次の境界

今回は提案をカーネルへ自動適用しない。次は、形状とELFの識別情報、測定単位、ページ予算を持つ
提案を検査し、既存の起動上限へ渡す経路を作る。この固定配置では解析式を基準にし、回帰は比較用として残す。
モデルの予測が小さ過ぎても上限を黙って拡大せず、拒否・回収と明示的な再計画で扱う。
学習済みモデル、任意入力、複数Agentの競合や一時バッファを含む負荷への一般化は未検証である。

既存の `infer-quota-approve / infer-quota-denied / infer-mem-fault / infer-mem-budget` の4ケースも
同じカーネルで合格した。記録は `native-os/out/sized-regression-results.json`。
今回のQEMU確認は計測24回と回帰4回であり、登録済み全104ケースの再実行ではない。
計測後のrunner修正はimport順の整形と、旧評価器用の起動情報の互換性修正である。
サイズ実験の識別情報とゲストバイナリは変えておらず、保存した計測ログを再解析できる。
