# Native OS の品質改善（2026-09-21）

対象は直近1週間の native OS の変更で、基準は `c46879e0`。
操作契約、永続記録、同期承認、非同期承認と試験ランナーを点検した。
既存の起動定義、権限、CPU上限、依存関係は変更していない。

## 改善した点

| 問題 | 修正と根拠 |
| --- | --- |
| 実行開始時の期限切れが RAM の Interrupted にだけ反映され、永続記録が Approved のまま残る | 拒否応答の前に変更後の状態を保存する。状態が変わらない拒否では追記しない。回帰テストで修正前の失敗と修正後の成功を確認 |
| 実行回数10や11が、期待する1回の部分文字列として合格する | 結果行を完全一致で比較し、行の重複も拒否。承認判断の状態と実行回数も厳密に照合。回帰テストで修正前の誤受理を確認 |
| 永続化試験が任意の停止状態や panic を含むログでも復旧試験へ進む | ケースごとの停止状態と先行保存の順序を照合。異常診断があれば2回目の起動を行わない。panic を見逃す再現テストを追加 |
| 保存先にカンマがあると QEMU の引数が分割される | 既存のパス変換を共通化し、両ジャーナルランナーにも適用。空白とカンマを含む一時ディレクトリで実際に組み立てる引数をテスト |

シリアル入力の保証も明確にした。消去できるのはゲスト UART の FIFO であり、
ホスト側の stdin / pipe や転送中の入力まで破棄する保証はない。
信頼された入力元が今回のプロンプトを確認してから送信する必要がある。

## 検証の範囲

修正は親担当が行い、承認処理とランナーを別々の読み取りレビューで確認した。
独立レビュー後の差分に追加の不具合指摘はなかった。実行試験は親担当が担当した。

QEMU は固定された Windows 上の x86-64 / UEFI 構成を使う。
実機、ホスト側に滞留した入力の配送、複数操作、人による対話入力は今回の実証範囲外。

## 実行結果

- Rust: 66/66成功。期限切れの記録漏れを再現したテストを含む。
- Python: 39/39成功。実行回数の部分一致と panic の見逃しは、修正前の失敗を確認した。
- QEMU: 操作契約5、承認12、永続復旧7の計24/24成功。
- Rustfmt、ホストとカーネルの Clippy、変更した判定器と共通処理の Ruff、差分検査、文字化け検査は成功。
- 変更差分と新規ファイルの Gitleaks 検査は検出0件。

それ以外の起動・メモリ・IPC等の45ケースは今回再実行していない。
新しい期限切れ分岐の永続化コールは単体テストで検証し、実際のディスク書き込みと復旧は
既存の QEMU ケースで回帰確認した。期限切れ実行専用の新しい QEMU ケースは追加していない。
