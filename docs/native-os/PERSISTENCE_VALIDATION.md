# M5a：操作記録の永続保存と再起動時の照合

## 実装範囲

PR #123 の操作契約にチェックポイントを接続した。従来と同じ Ring 3 クライアントと資料サービスが
RAM 資料の読み取りを要求し、Proposed / Approved / Running / Completed をディスクへ保存する。
Running を保存し flush・読み戻しを確認する前に、読み取り処理へ進まない。
書き込み失敗はカーネルを停止させる。保存に失敗したまま成功を返したり、RAM だけで継続したりしない。

再起動後は記録を読み、Completed は完了、Proposed / Approved は Interrupted、Running は Unknown と判定する。
ユーザープロセスは起動せず、承認・ハンドル・期限を現行権限として復元しない。完了した操作を再実行しない。
これは安全に停止して結果を照合する最初の段階であり、自動再開や再承認 UI は未実装。

## 保存形式とデバイス

- 32 KiB（64 × 512 bytes）の専用 raw イメージ。runner が毎回新しいディレクトリ・ファイルとして作る。
- QEMU の ISA IDE master を固定ポートで PIO 操作。DMA、割込み駆動、実機のデバイス探索は行わない。
- IDENTIFY の容量とセクター0の専用ラベルを検査。不一致なら書き込まず停止。ゲストはフォーマットしない。
- セクター1〜8が追記専用の記録領域。書き込み API はこの範囲以外を拒否する。
- 記録は形式識別子、連番、状態、tick、完全な操作契約、前レコードの CRC、当該レコードの CRC32。
- 版、予約領域、連番、CRC、契約の同一性、状態遷移、途中の空白を検査。不正な末尾を黙って捨てない。
- 書き込みは1セクターずつ行い、FLUSH CACHE と読み戻しの一致を確認してから索引を進める。
- 容量不足時は再利用・上書きをせず拒否。実行開始前に開始・結果用の2枠を要求する。

CRC は偶発的な破損の検出用であり、改ざんに対する認証ではない。暗号化・MAC・ロールバック防止は未実装。
記録中の古いハンドルは照合資料であり、復元可能な権限として使わない。記録には資料本文を含めない。

## 試験

各シナリオで同じイメージを2回の独立した QEMU プロセスへ接続する。
復旧時にユーザープロセスを起動しないこと、実行と権限復元が0であること、前後のディスク SHA-256 が一致することを確認する。

| ケース | 第1起動・障害入力 | 第2起動で要求する結果 |
| --- | --- | --- |
| persist-complete | 正常な操作と4状態の保存 | Completed、再実行なし |
| persist-interrupted | Approved の flush 後に停止待ちし、ホストが QEMU を強制終了 | Interrupted、再承認なしには実行しない |
| persist-unknown | Running の flush 後に同様に強制終了 | Unknown、無条件の再試行なし |
| persist-torn | Approved レコードの後半をゼロにした試験用書き込み後に強制終了 | journal-corrupt、上書きなし |
| persist-corrupt | 保存した記録の1バイトを runner が変更 | journal-corrupt、上書きなし |
| persist-truncated | イメージを短く切り詰める | disk-size、上書きなし |
| persist-full | 正常な記録形式で全8枠を埋める | 追加を拒否し、最後の Completed を報告 |

強制終了は所定のチェックポイントがログに出た場合だけ障害注入として扱う。
単なる時間切れ、UEFI の起動失敗、想定外のエラーを成功にはしない。
記録の途中書き込みは決めた位置で破損を作るモデルであり、全種類の物理電源断を再現したものではない。
満杯ケースは runner が2操作分の妥当な記録を構成する。実行サービス自体は引き続き1操作の試験である。

## 検証と限界

Windows / Rust 1.96.0 / 固定 QEMU 11.1.0 / 既存 UEFI を使用。既存環境を再利用し、新規依存は追加していない。
新しいディスク I/O と runner の書き込み先、スクリプト、依存・hooks・CI・認証情報・通信経路を確認した。
ゲスト NIC、ホストの実ディスク、ホーム共有、クラウド送信は使わない。CI・hooks は変更しない。
ローカル生成物は ignored の native-os/out/ と native-os/target/ に限定する。

2026-09-20 の結果：QEMU 57/57シナリオ（既存50、二段階起動の永続化7）、Rust 60/60、Python判定器30/30。
永続化の7シナリオは計14回の独立した QEMU 起動を含む。
Rustfmt、ホスト・x86_64-unknown-none の Clippy（警告をエラー扱い）、新規 Python の Ruff、差分検査が成功。
開始時のコンパイルではデコード添字の型推論エラーを修正した。修正後のビルド・単体試験・全シナリオは成功した。
ステージ済み差分の Gitleaks 検査で秘密情報の検出はなかった。GitHub 側のチェックは PR 提出後に別途確認する。

QEMU プロセスの停止・再起動までの検証であり、ホスト自体の電源断、実機ディスク、一般的なファイルシステム、
複数サービスの取引、任意の外部副作用の exactly-once は保証しない。承認入力は引き続き試験用で、AI 推論は接続していない。
