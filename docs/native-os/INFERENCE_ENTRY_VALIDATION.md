# M6a: 制限付き推論の入口

独立した Ring 3 の ELF で整数モデルを計算し、読み取り範囲の候補を提案する。
候補は承認を意味しない。カーネルが表示した操作を信頼済み COM1 入力から承認した場合だけ、
既存の資料サービスが同じ操作を一度実行する。

これは手設計した重みと合成入力による、小さな分類器の統合試験である。
学習済みモデル、自然言語理解、要約、LLM の実用性を検証したものではなく、M6 全体の完了とも扱わない。

## 計算と入力

`apps/inference-client/` は外部依存、allocator、浮動小数点を使わない `no_std` package。
PID 0 の Client ELF をこの ELF に置き換え、PID 1 の資料サービスを再利用する。
カーネルはモデル計算を行わず、ロードしたプロセスの専用データページへ入力をコピーする。

| 項目 | 形式と制限 |
| --- | --- |
| モデル | 24 bytes。`ELYSINF1`、版1、入力数2、出力数2、予約0、i8重み4個、little-endian i16 bias 2個、FNV-1a 32-bit checksum |
| 値の範囲 | 重み −8〜8、bias −64〜64、入力0〜16。積和は i32 に収まる |
| 起動入力 | `0x60000400` の8 bytes。版1、特徴数2、little-endian i16の x/y、予約0を2 bytes |
| 入力の所有者 | ELF 公開前にカーネルがコピーし、起動後は PID 0 の専用 RW/NX ページに置く |
| 静的データ | linker が `.data/.bss` の終端を入力領域の手前に制限し、衝突をビルド時に拒否する |
| 出力 | 先頭8 bytes、先頭16 bytes、または棄権。権限・対象・予算を生成しない |

手設計したモデルは `scores = [2*x - y, -x + 2*y]` を計算する。
第1スコアが大きければ8 bytes、第2が大きければ16 bytes、同点なら提案せず終了する。
同じ ELF に `(4,1)` と `(1,4)` を渡し、計算結果と提案が変わることを試験する。
入力は実行時に volatile 読み取りを行い、モデルのデコードも実行時に通す。

モデルはこの ELF に同梱した試験用データに限定する。checksum は偶発的な破損の検出であり、
署名、認証、悪意あるモデルの安全性の証明ではない。資料本文をモデルに渡す処理はまだない。

## 承認と隔離

既存の起動定義をそのまま使い、各プロセスはページテーブル込みで32 owned frames以内。
Client は累積1024 ticks、Service は64 ticks以内で停止する。厳密な CPU 時間課金ではない。
ELF の RX/RW は各4 KiB以内、専用スタックも4 KiB。FPU/SIMD の文脈保存は引き続き未対応。

推論クライアントは自分の通信・資料ハンドルだけを受け取り、計算結果から読み取りの長さを選ぶ。
共有クライアントの試験で、未承認の実行、自己承認コマンド、承認後の長さ変更、二重実行を拒否する。
推論の異常系でも非同期承認 hook を設定し、要求が来た場合に試験用の自動承認へ落ちないようにする。
正常提案を行うモード56/57は、[非同期承認](ASYNC_APPROVAL_VALIDATION.md)の処理継続と状態参照を使う。

拒否・期限切れ後も Client は結果を受け取り、Service は相手の切断を受けて終了する。
提案前のモデル拒否、入力拒否、棄権、意図的な #UD、無限ループも同じ回収経路に入る。
カーネルとホスト判定器の両方が、操作回数、停止理由、両者の回収、空きフレーム数の復元を検査する。

## 起動試験

| ケース | 入力・注入 | 期待する結果 |
| --- | --- | --- |
| infer-approve | `(1,4)`、approve | 16-byte提案、Completed、実行1回 |
| infer-short | `(4,1)`、approve | 8-byte提案、Completed、実行1回 |
| infer-deny | deny | Denied、実行0回 |
| infer-timeout | 無入力 | Interrupted、実行0回 |
| infer-invalid | 余分な語を含む承認 | Interrupted、実行0回 |
| infer-replay | approveを二度送る | Completed、実行1回 |
| infer-model | モデルの1 byteを変更 | モデル拒否、提案なし |
| infer-oversized | 入力ヘッダーの特徴数を3に変更 | 入力拒否、提案なし |
| infer-range | xを32767に変更 | 入力拒否、提案なし |
| infer-abstain | `(1,1)` | 同点で棄権、提案なし |
| infer-budget | 提案前に無限ループ | PID 0を1024 ticksで停止、提案なし |
| infer-fault | 提案前にUD2 | PID 0のRing 3 #UDを捕捉、提案なし |

提案のある6ケースは、新しい32 KiBの試験用ディスクを使い、終了後に同じディスクで再起動する。
古い承認を再送しても権限・プロセスを復元せず、ディスクを変更しないことを要求する。
提案のない6ケースは、Empty・実行0回・ディスク全体の不変を要求する。
`infer-oversized` は特徴数の上限検査であり、巨大な可変長 payload を取り込む試験ではない。

```powershell
python native-os/tools/boot_test.py --case infer-approve --qemu <qemu-system-x86_64.exe> --firmware-dir <share>
python native-os/tools/boot_test.py --case all --qemu <qemu-system-x86_64.exe> --firmware-dir <share>
```

人の入力を使う入口は `--case infer-approve --operator-manual` または `--case infer-short --operator-manual`。
自動試験はホスト側から承認を送るため、人による対話入力を検証したとは扱わない。
承認期限は500 ticks（公称100 Hzで約5秒相当）。試験用の短い設定であり、
割り込みの遅延があるため厳密な経過時間の上限ではない。

ログ、専用ディスク、ELF・ソースのハッシュは ignored の `native-os/out/` に残す。
生成物の配布、モデルのダウンロード、ホスト API の利用、外部通信は行わない。

## 今回の境界

固定した2プロセスと1操作だけを扱う。任意モデルの読み込み、特徴抽出、学習、自然言語の指示、
資料中の命令への耐性、GPU、Windows アプリ互換、実機動作は対象外。
今回の故障注入は提案前であり、承認待ち中の推論器の故障を新たに実証したとは扱わない。
COM1 ホストへの信頼、永続記録の認証、実電源断耐性の制限も従来のまま。
