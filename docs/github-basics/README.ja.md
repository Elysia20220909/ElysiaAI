# GitHubのリポジトリ直下ファイル・フォルダ一覧について

## 要約

- GitHubで、リポジトリ直下にあるファイルやフォルダの一覧が表示されている状態です。
- Gitに登録されているものは、`.` で始まる設定ファイルでも一覧に表示されます。
- 表に出ていること自体は普通の動きです。
- ただし、公開リポジトリの場合は、秘密情報が含まれていないか確認が必要です。

## 画面の意味

GitHubのリポジトリ画面では、プロジェクト直下にあるファイルやフォルダが一覧で表示されます。

- 左側: ファイル名またはフォルダ名
- 中央: そのファイルを最後に変更したコミットメッセージ
- 右側: 最後に更新された時期

たとえば、`README.md`、`package.json`、`.gitignore`、`.env.example`、`docs/`、`src/` などが並んでいる場合、それらはGitで管理されているものとしてGitHubに表示されています。

## `.` で始まるファイルについて

`.` で始まるファイルは、WindowsやUnix系の環境では隠しファイルのように扱われることがあります。

しかし、GitHubでは隠されません。Gitに登録されていれば、通常のファイルと同じように表示されます。

- `.gitignore`: Gitで無視するファイルを指定する設定
- `.dockerignore`: Dockerビルド時に除外するファイルを指定する設定
- `.editorconfig`: エディタの整形ルール
- `.env.example`: 環境変数のサンプル
- `.npmrc` / `.yarnrc.yml`: パッケージ管理ツールの設定

## 注意すること

表に出ていること自体は問題ではありません。大切なのは、見えてはいけない情報が含まれていないかです。

特に、次のような文字列や値が入っていないか確認します。

- APIキー
- パスワード
- アクセストークン
- シークレットキー
- 秘密鍵
- 本番環境の接続情報

確認するときの目印です。

```text
API_KEY
SECRET
TOKEN
PASSWORD
PRIVATE_KEY
.env
```

## 結論

これは、GitHubにアップロードされたプロジェクトの中身が一覧表示されている状態です。

伝統的な開発の作法としては、`.env.example` のようなサンプル設定は公開して、本物の `.env` や秘密情報はGitに入れません。

落ち着いて確認すれば大丈夫です。家の玄関に表札を出すように、公開してよい情報は見える場所に置き、鍵そのものは静かに奥へしまっておく、という感覚で扱うと安心です。
